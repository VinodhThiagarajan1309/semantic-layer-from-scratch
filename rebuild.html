Appendix

Rebuild the AWS sandbox

The two warehouses were shut down on November 7, 2026, so they stop costing money. This page explains how to bring them back exactly as the book used them, in about 30 minutes.

Everything the book built in Stardog is still there: the ontology, the rules, the roles, the two data sources and the three virtual graphs. What's gone is the AWS side, meaning the Aurora PostgreSQL cluster, the Redshift Serverless workgroup and their network. Until you rebuild them, any query that reaches a virtual graph fails with a connection error. Queries over the model graphs still work, for example the ontology query in Chapter 16.

Rebuilding is five scripts, a data load and one password change in Studio. The scripts are in the repo under code/aws/. Every script can safely be run twice: each one reuses anything that already exists.

1. What existed, and the settings it used

2. Bring it back

Before you start: you need AWS CLI v2, signed in with aws login, and Python 3.12 with psycopg2-binary, redshift_connector and python-dotenv. You also need a copy of Stardog's knowledge-kits repo for the CSVs. In config.sh, set BUDGET_EMAIL to your address.

cd code/aws
bash 00_budget.sh      # once per account: anomaly monitor + daily email
bash 01_network.sh     # subnets, security group, DB subnet group (~1 min)
bash 02_aurora.sh      # Aurora PG 16.14 Serverless v2, 0-1 ACU (~10-15 min)
bash 03_redshift.sh    # Redshift Serverless 4 RPU + daily usage limit (~5 min)
C360_DATA=<knowledge-kits>/examples/c360/data python load.py all

The scripts generate new passwords and write them, along with the new host names, to code/aws/.env.aws (chmod 600; never commit it). load.py should print 500 customers and 2,500 purchases.

Then reconnect Stardog. The data sources still hold the old passwords. In Studio, go to Data Sources, edit aurora_c360 and then redshift_c360, and paste the new jdbc.password from .env.aws. Check that jdbc.url matches the new host. Because the cluster and workgroup names are the same, the host names usually come back the same too. Leave the other options as they are. If you deleted the data sources, recreate them from the two .properties templates, then recreate the virtual graphs from the .sms files in code/aws/stardog/ (Chapters 8 and 9; untick "Auto-generate mapping").

Check it worked with the catch-all query, in Studio as an admin or as hr_user:

PREFIX : <tag:stardog:api:ecomm:>
SELECT ?name (SUM(?price * ?qty) AS ?spend)
FROM <tag:stardog:api:context:virtual>
WHERE {
  ?c a :Customer ; :name ?name ; :address/:state "Wisconsin" .
  ?o :purchasedBy ?c ; :purchasePrice ?price ; :quantity ?qty .
} GROUP BY ?name ORDER BY DESC(?spend) LIMIT 3

Expect Carolyn Inworth at $502,529.42 first. If you get it, both warehouses, the mappings and the join are all back. If Aurora was paused, the first one or two runs can fail with "The connection attempt failed" for up to a minute while it wakes; run it again. (Stardog may print the sum with float noise, such as 502529.4200000000419; that is the same number.)

Your IP changed? The security group lets in only Stardog Cloud and the IP you ran 01_network.sh from. If DBeaver or load.py can't connect from a new network, run 01_network.sh again: it adds your current IP and keeps the existing rules. Stardog itself is not affected.

3. What it costs, and how to shut it down again

While it exists, the sandbox costs about $0.25 to $0.50 a day even when idle. Almost all of that is AWS's public IPv4 charge ($0.005 an hour per address) on the Aurora instance and the Redshift endpoint, plus a little Aurora storage. Compute is close to zero while both are paused. Each query that wakes Redshift is billed for at least 60 seconds at 4 RPU, which is about 2.5 cents.

What this sandbox actually cost, from AWS Cost Explorer (amounts are rounded to the cent):

PeriodBillWhere it went
Sep 23 to 30, 2026 (the build)$3.74Mostly public IPv4 and Aurora
October 2026 (a full month)$10.55Public IPv4 (VPC) $7.44 · Aurora (RDS) $2.18 · S3 $0.23 · Cost Explorer API $0.05 · tax $0.65 · Redshift $0.00
Nov 1 to 6, 2026$1.63Same pattern, until the teardown on Nov 7

Note what dominates: public IPv4 addresses cost more than both databases put together. An idle sandbox is cheap per day but not free, so tear it down between uses.

When you're done, tear it all down:

bash 99_teardown.sh          # Redshift, Aurora (no final snapshot), SG, subnets, then a leftover check
bash 99_teardown.sh --all    # also removes the cost-anomaly monitor

Teardown keeps no snapshot, because the data reloads from the CSVs in a minute. The last section of the script lists anything still tagged Project=stardog-c360, and it should print nothing.
